8) Gateway:
    a) Publish a graphql list of domains
    b) Allow the upload of a binary to a given domain



What classes are involved here?

    1) BinaryStorageController and the MultipartParser/etc: the web-related classes for handling
        binary storage coming in from the web
    2) BinaryStorageService: high-level coordinator between the actual storage and the binary
        references stored in the graph
    3) BinaryStorageAdapter: the actual implmentation of storage (block storage, S3, HDFS, etc)




10) Binary storage:

    * The controller accepts a multipart upload
        * The controller passes the DataBuffer over to an upload service
            * The upload service stores each file via a storage adapter by its upload ID
                * The storage adapter writes out the file data and returns the SHA1 and MD5 hashes
            * The upload service then consults the graph to see if the hashes exist.
                * If they do exist, the storage service tells the adapter to delete the temp file
                * If they do not exist, the storage service tells the adapter to commit the temp file
                * In either case, the end result will be a data node ID with the associated hashes
            * The service will pass back each upload ID with its corresponding node ID
        * The controller returns a map of upload IDs that map to the coresponding node IDs
